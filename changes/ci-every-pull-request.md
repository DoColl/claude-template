bump: minor

- `ci-workflow`: the CI skeleton runs on every pull request and every push to the default branch, with no `paths` or `paths-ignore` filter. With a ruleset that requires the CI checks, a documentation-only pull request got no run, so its required checks never reported and it could not be merged without a bypass. A new `changes` job (on `ubuntu-slim`, a few seconds) says whether anything outside the documentation set (`docs/**`, `**.md`, `LICENSE`, `.gitignore`) changed; the project's costly jobs declare `needs: [security, changes]` and `if: needs.changes.outputs.code != 'false'`, and GitHub counts a job skipped that way as a passing required check. The job fails closed: `'true'` unless the diff was read and every file in it is documentation. The call to `security.yml` never waits for it.
- `ci-workflow`: new guard `31-ci-workflow.sh`. CW-1: the CI workflow runs on pull requests and pushes, with no path filter. CW-2: the job that calls `security.yml` waits for no other job and has no `if:`. CW-3: the `changes` job's script, between `# harness:changes-begin` and `# harness:changes-end`, is run on a table of sixteen changes built in scratch repositories; its output and its step's header are pinned, and the job has no `if`, `continue-on-error`, `shell` or `defaults` key. The jobs that read it test `!= 'false'`, so an empty verdict runs them.
- `auto-merge`: the documentation fast path is gone. `promote-docs`, the `pull_request` job that merged a documentation-only pull request at once without CI, is removed, with its trigger and the documentation rule of the check of what the merge wrote. Every pull request now merges through `promote-from-ci`, after a green CI run, so the secret scan and the gate judge every merged pull request, documentation included; one is held, documentation-only or not, by cancelling its CI run. New check AM-11: the workflow's only trigger is `workflow_run`. AM-4, AM-7 and AM-10 lose their `promote-docs` pins; AM-7 now takes the base branch from the gate only.
- `ci-security`: `security.yml` has no `push` trigger on documentation paths any more; the CI workflow calls it on every push and pull request.
- `weekly-digest`: the docs-only set is built in (`DEFAULT_DOCS_RE`), since `auto-merge.yml` no longer declares one; and the digest reads whether the CI workflow filters its triggers on paths: without a filter, a docs-only pull request with no CI run is listed after 1 h like any other. A docs-only pull request with no CI run, where `auto-merge` is installed, is listed with the fix (drop the CI workflow's path filter, or merge it by hand).

By hand: `.github/workflows/ci.yml` is a seed and is not rewritten. Remove every `paths` and `paths-ignore` filter from its triggers (or from your own CI workflow's, if it calls `security.yml`): `auto-merge` no longer merges a pull request that has no CI run, and `security.yml` no longer scans documentation-only pushes by itself. Then, to keep the build off documentation, copy the `changes` job from the kit's `modules/ci-workflow/files/.github/workflows/ci.yml` and give each costly job `needs: [security, changes]` and `if: needs.changes.outputs.code != 'false'`; where `ci-workflow` is installed, CW-1 to CW-3 turn the gate red until the file has that shape. Where a ruleset protects the default branch, require the CI jobs by their names (`Security / Enforcing (gitleaks + gate)` and your own): a job skipped on documentation counts as passed. Open one pull request that only touches a Markdown file and check that its run starts, that `Security` runs and that your jobs are skipped.
