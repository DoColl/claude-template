- `auto-merge`: before each merge call, retries included, the merge step reads the pull request, the base branch's tip and, when the tip moved, the head's merge base with it again. A pull request merged already by this workflow's token (a call that merged and answered an error) goes to the check below, and so does one the last call merged; one merged by hand meanwhile is left alone. A retargeted one, or one whose merge base moved — a commit of its head landed since the gate, so the merge would no longer write what the gate listed — is left ready and unmerged until the workflow is re-run or someone merges it by hand. A tip moved by unrelated merges does not stop it. Each gate holds a range that comes back without its merge base.
- `auto-merge`: after each merge, a new step (`Check what the merge wrote`) lists the commit GitHub created against its first parent and runs the gate's rules on it — `CLAUDE_GATE_RE` and `PROJECT_GATE_RE`, the weakened tests under `TEST_HOLD_RE` and, in `promote-docs`, anything but documentation — and turns the run red when one of them matches, or when the listing reaches 300 files or cannot be read. The gate's listing is what GitHub's merge writes only while GitHub's merge starts from the merge base its compare names, which a live test with two merge bases observed and nothing documents. The step's documentation rule is `promote-docs`' own, so a project's wider documentation set is the check's too. AM-10 pins that step, the merge call's success branch and the merge steps' outputs, and refuses in the workflow what would make what runs differ from its text or let the check pass (a carriage return or a NEL, `continue-on-error`, `BASH_ENV`, `GITHUB_ENV`, `GITHUB_PATH`, `${!…}`, `sudo`, `PATH`/`HOME` assignments, a `.jq` file, `defaults`/`shell` keys however quoted, explicit keys, functions beyond the three the workflow defines, empty quotes inside a word, a continuation that does not go on with an option, a `PUT` beyond the merge calls, a `${{ }}` outside the value of an `if`, a `group` or an env key or inside a block scalar). AM-7 now counts three compare calls per merging job and names the tip on four lines, and pins the hand-over of the tip and the merge base, the reads before each merge call and the read after the last one; AM-8 counts the per-file facts of both listings.

By hand: a project that added a dispatch after the merge (`docs/conventions/auto-merge-policy.md` § After the merge) moves it after the new step and adds `&& steps.check.outcome == 'success'` to its `if`, so that nothing is dispatched after a red check.
